# cs-portfolio
My SNHU Computer Science portfolio


Project Summary
The DriverPass project was about creating a system for a driving school that wanted to make things easier for both students and employees. The goal was to let students handle more things online instead of having everything managed manually. The system needed to make scheduling lessons and keeping track of student information easier.
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
What I Did Well:
I think I did a good job understanding what the client wanted and using that information to plan the system. I tried to make sure the design made sense and covered the main things the business needed. Working on this project also helped me understand how important it is to plan everything out before actually building a system.
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
What I Would Improve:
If I could go back and change something, I would spend more time reviewing my documents and making sure everything was explained clearly. I would also look more closely at how the different parts of the system work together. I think this would make the design easier for someone else to understand and use when building the actual system.
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Understanding the User's Needs:
I used the information provided by the client to figure out what problems the system needed to solve. DriverPass wanted to make scheduling and managing information easier, so I focused on designing a system that would help with those tasks. Understanding the user's needs is important because the system has to work for the people who will actually use it. If you don't understand what they need, you could end up creating something that doesn't solve their problems.
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
My Approach to Software Design:
When I design software, I think it's important to understand the problem first before trying to figure out how to solve it. I would start by looking at what the user needs, then break the system down into smaller parts so it's easier to plan. In future projects, I would spend more time reviewing the requirements and checking my design before moving forward. I think this would help me catch mistakes earlier and build better systems.
